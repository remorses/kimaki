A message in a session thread **interrupts the agent at once** and becomes the next instruction. To wait for the current run instead, [queue](../features/queue) the message.

| You want to...                                 | Send                                         |
|------------------------------------------------|----------------------------------------------|
| Redirect the agent right now                   | a normal message                             |
| Add a follow-up for after the run finishes     | `message. queue` or [`/queue`](../features/queue) |
| Ask a side question without disturbing the run | `question. btw` or [`/btw`](../features/btw) |
| Run a shell command, no model turn             | `!pnpm test` (see [Shell Commands](../features/shell-commands)) |
| Run an OpenCode command                        | `/review args` as a message, or its `/<name>-cmd` slash command |

## A normal message interrupts

When the agent is busy and you send a normal message, Kimaki does three things in order:

```diagram
  You send a message
        │
        ▼
  ┌───────────────────────┐    ┌────────────────────┐    ┌──────────────────────┐
  │ cancel pending        │──▶ │ interrupt the      │──▶ │ deliver your message │
  │ questions and         │    │ current run        │    │ as the next prompt   │
  │ permission prompts    │    │ (tool call stops)  │    │                      │
  └───────────────────────┘    └────────────────────┘    └──────────────────────┘
```

There is no timer: the interrupt is immediate, even during a long build or test run. This is what you want when the agent is heading the wrong way.

The session keeps its agent, model, and history. Only the running step stops; the agent sees your message next and continues from there. An interrupted turn gets no footer.

## Queued messages wait

A message that ends with `. queue` (or a line with only `queue`), and every `/queue`, waits until the current run finishes. Kimaki confirms it with:

```
-# Queued at position 1. Delete the original message to remove it, or use /clear-queue position:1
```

When OpenCode delivers it, Kimaki posts `» **Tommy:** your message` and the confirmation changes to `Queued message sent`.

- **Delete** the Discord message to remove it from the queue.
- **Edit** it to change the text; the edited message moves to the end of the queue.
- **`/clear-queue`** removes all queued messages, or one with `position:`.

The queue lives in OpenCode, so it survives a Kimaki restart. See [Queue](../features/queue).

## Stopping everything

`/abort` stops the run and also clears the queue, cancels pending questions and permission prompts, stops running `!` shell commands, and cancels a pending [sleep](../features/sleep).

```
/abort
```
