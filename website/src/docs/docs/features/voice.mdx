Record a **voice message** in Discord and Kimaki transcribes it, then processes it as a normal prompt. Speaking is often faster than typing a long instruction, especially from your phone.

## How it works

```diagram
  voice ──▶ transcription ──▶ "📝 Transcribed" ──▶ session
              ▲
              │ project file tree for accuracy
```

1. You record a voice note in the thread.
2. Kimaki sends the audio to a transcription model.
3. The transcribed text appears in the thread prefixed with **📝 Transcribed message:** and is sent to the agent.

## Queue a voice request

Say **"queue this message"** with the task to wait until the current turn finishes. Kimaki removes the queue instruction from the transcription. If the session is idle, the request starts immediately.

```text
Queue this message. Add tests for the login form.
```

## Create a separate chat

Ask **explicitly** for a new chat, session, or thread. A plain new-chat request starts fresh with no conversation history:

```text
Fix the login bug. Create a new chat for this.
```

To keep the current conversation context, explicitly request a **side chat or fork** from a thread that already has a session:

```text
Explain the parser. Create a side chat with the current context for this.
```

Both routes send the task **only to the destination thread** and preserve the source's pending questions and permission requests. Routing takes priority over queueing. The destination inherits the current working directory. A voice note in a project channel already creates a fresh thread.

**Conversational phrases** such as "by the way" do not move a voice request to another chat. Include a task with the routing instruction; a routing-only note does not start an empty turn. You can also say "use the plan agent" with either route.

## Accuracy from your project file tree

Transcription of code is hard: file names and function names are not normal words. Kimaki improves accuracy by feeding the **project's file tree** into the transcription prompt, so when you say a file path or a function name, the model recognizes it from your actual codebase.

<Aside>
<Tip>
Say file and function names naturally. Because the transcriber sees your file list, "open thread session runtime" is far more likely to come back as `thread-session-runtime.ts`.
</Tip>
</Aside>

## Models and setup

Kimaki auto-detects the provider from the API key you configure for audio:

- **OpenAI** key (starts with `sk-`) → uses `gpt-audio`.
- **Gemini** key → uses `gemini-2.5-flash`.

You'll be prompted for an audio API key during setup, or you can add one later from Discord when you first send a voice message.

**Queue, chat, and agent detection require OpenAI or Gemini transcription.** The gateway's key-free Whisper fallback only transcribes speech; it does not interpret these routing instructions.

## Sending audio back

Kimaki can also speak: when you ask for audio of some text, the agent can generate speech with `kimaki tts` and post it to the thread. See the [Commands reference](../reference/commands) for the `tts` and `upload-to-discord` CLI subcommands.
