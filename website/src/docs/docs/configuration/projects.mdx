A **project** is a directory on your machine linked to a Discord channel. You manage projects with the `kimaki project` commands. For the underlying model, see [Channels & Threads](../core-concepts/channels-threads).

```bash
kimaki project add /code/web-app   # create #web-app for this directory
kimaki project list                # every project and its channel
```

## Adding a project

```bash
# Add the current directory
kimaki project add

# Add a specific directory
kimaki project add /code/web-app

# Pick the server when your channels are in more than one
kimaki project add ./web-app --guild 123456789
```

The channel is named after the folder and goes into this machine's **`Kimaki <machine>`** category. `<machine>` is the hostname; change it with `--machine-name`. If another machine already has a channel with the same name, the new one gets a `-<machine>` suffix.

Adding a directory that already has a channel prints `Already added` and creates nothing.

<Aside>
<Tip>
You can also ask the agent. On first start Kimaki opens an onboarding thread where the agent finds your git repositories and runs `kimaki project add` for the ones you pick. Any later session can do the same.
</Tip>
</Aside>

## Listing projects

```bash
kimaki project list
kimaki project list --json   # channelId, directory, guildId per project
```

## Removing a project

Kimaki V2 has no command to remove a project. Deleting the Discord channel does not remove the mapping from Kimaki's database: `kimaki project list` still shows it, and `kimaki project add` for that directory reports `Already added`. The directory on your machine is never touched.

## Running more than one bot

Each Kimaki bot keeps its projects in its own data directory (`~/.kimaki` by default). To run a second, isolated bot, give it another data directory and lock port; see [Advanced Setup](../guides/advanced-setup).

```bash
KIMAKI_LOCK_PORT=31001 kimaki --data-dir ~/.kimaki-test
```
