**Verbosity** controls how much of the agent's tool activity appears in a thread. There are two levels, set per channel:

```diagram
   tools  ──▶  text, file edits, and tools with side effects; hides reads and searches  (default)
   text   ──▶  text, file edits, and errors; hides all other tools
```

| Level | What it shows |
|---|---|
| **Text and tools** (`tools`) | Text, file edits, and tool calls with side effects. Hides `read`, `glob`, `grep`, and shell commands that only read. **Default.** |
| **Text only** (`text`) | Text, file edits, and errors. Hides every other tool call. |

At both levels you always see the agent's text, file edits (`-# ◼︎ edit *file.ts* (+3-1)`), errors, `!` shell command output, and the footer. Reasoning is never shown.

## Setting verbosity

Run **`/verbosity`** in a channel or one of its threads and pick a level. The setting is stored per channel and **applies immediately**, including to sessions that are already running.

From the CLI (the bot must be running):

```bash
kimaki channel verbosity text                      # channel of the current directory
kimaki channel verbosity tools --channel 123456789
```

## How `tools` decides

At the default level, Kimaki hides tool calls that only read:

- `read`, `glob`, and `grep`.
- Shell commands the agent marks as having no side effects (`hasSideEffect: false`). Kimaki's OpenCode plugin adds this field to the shell tool, so the agent marks each command.

Everything else shows as a subtext line, for example `-# ┣ shell _run the test suite_`. Subagent tool calls follow the same rules and show in the parent thread with the agent name: `-# ┣ general ⋅ shell _run the migrations_`.
