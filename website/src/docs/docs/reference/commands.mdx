A complete reference of Kimaki's **Discord slash commands**, **message shortcuts**, and **CLI subcommands**. For deep dives, follow the links.

```bash
# start the bot (onboarding on first start)
npx -y kimaki@latest

# then, from any shell or agent
kimaki send --channel <channel-id> --prompt 'fix the failing test'
kimaki session list --all
```

## Session slash commands

Most of these work only inside a **session thread**. `/resume` works only in a **project channel**. `/new-session` and `/diff` work in both.

| Command                                | Description                                                                                   |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `/new-session prompt files? agent?`    | Start a new OpenCode session. `files` autocompletes project files, comma separated            |
| `/resume session`                      | Resume an existing OpenCode session in a new thread ([docs](../core-concepts/sessions))       |
| `/abort`                               | Stop the current run and clear the queue. Also cancels pending questions and running `!` shells |
| `/btw prompt`                          | Ask something without polluting or blocking the current session ([docs](../features/btw))     |
| `/fork`                                | Fork the session from a past user message ([docs](../core-concepts/sessions))                 |
| `/fork-subagent`                       | Fork a subagent task session into a new thread                                                |
| `/compact`                             | Compact the session context by summarizing the history                                        |
| `/undo`                                | Undo the last turn. File changes are kept                                                     |
| `/redo`                                | Redo the previously undone turn                                                               |
| `/context-usage`                       | Show token usage and context window percentage                                                |
| `/session-id`                          | Show the OpenCode session ID of this thread and how to open it in OpenCode                    |
| `/diff`                                | Show the git diff as a shareable URL ([docs](../features/diff-viewer))                        |

## Queue slash commands

| Command                              | Description                                                                  |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| `/queue message`                     | Send a message after the current run finishes ([docs](../features/queue))    |
| `/queue-command command arguments?`  | Queue an OpenCode command to run after the current run finishes              |
| `/clear-queue position?`             | Remove queued messages. `position: 1` removes only the next one              |

You can also remove a queued message by **deleting** its Discord message, or change it by **editing** it.

## Model and agent slash commands

In a session thread these change the **session**. In a project channel they set the **default for new sessions** in that channel.

| Command          | Description                                                                                          |
| ---------------- | ---------------------------------------------------------------------------------------------------- |
| `/model`         | Set the model for this session or channel ([docs](../getting-started/model-switching))               |
| `/model-variant` | Change the thinking level of the current model                                                       |
| `/agent`         | Set the agent for this session or channel                                                            |
| `/verbosity`     | Set what the bot shows in this channel: `tools` or `text` ([docs](../configuration/verbosity))       |
| `/login`         | Connect an OpenCode provider ([docs](../getting-started/subscriptions)). Owner or admin only         |
| `/transcription-key` | Set the OpenAI or Gemini API key for voice transcription and speech ([docs](../features/voice)). Owner or admin only |

## Worktree slash commands

| Command                                  | Description                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `/new-worktree name? base-branch?`       | Start an isolated Git worktree session. In a thread it forks the context ([docs](../features/worktrees)) |
| `/merge-worktree strategy? target-branch?` | Merge this worktree into a local branch. `strategy` is `rebase` (default) or `squash`           |
| `/worktrees`                             | List worktrees, delete a safe checkout, or toggle automatic worktrees                             |
| `/cwd path?`                             | Show or change this session working directory (a project subfolder or a linked worktree)          |

## Other slash commands

| Command  | Description                                                                         |
| -------- | ----------------------------------------------------------------------------------- |
| `/tasks` | List scheduled tasks, run one now, or delete it ([docs](../features/scheduled-tasks)) |

## Dynamic slash commands

Kimaki reads the agents, commands, and skills of your projects from OpenCode and registers one slash command for each. See [OpenCode Commands](../features/opencode-commands).

| Command                   | Source                 | Options                              |
| ------------------------- | ---------------------- | ------------------------------------ |
| `/<agent>-agent`          | primary agents         | `prompt?`, `variant?` (thinking level) |
| `/<command>-cmd`          | OpenCode commands      | `arguments?`                         |
| `/<skill>-skill`          | skills                 | `arguments?`                         |

**MCP prompts** get no slash command. Send them as a message, like `/server:prompt args`, or queue them with `/queue-command`. Discord allows 100 commands per server; skills are dropped first when there are too many.

## Message shortcuts

| Shortcut                  | Effect                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| plain message             | Interrupts the current run and sends your message ([docs](../core-concepts/message-handling)) |
| `!<command>`              | Runs a shell command in the session folder. Does not interrupt the agent ([docs](../features/shell-commands)) |
| `... . queue`             | Queues the message for after the current run ([docs](../features/queue))                  |
| `... . btw`               | Forks the context into a side thread ([docs](../features/btw))                            |
| `/<command> args`         | Runs an OpenCode command when the project has it, else sends the text as a prompt          |
| voice message             | Transcribed, then routed like text ([docs](../features/voice))                            |
| attachment                | Saved locally and sent to OpenCode as a file ([docs](../features/images))                 |

## CLI subcommands

Every command except `tunnel` accepts `--data-dir <path>` (default `~/.kimaki`). Commands with `-s, --session <id>` take a session ID, a Discord thread ID, or a thread URL. Inside a Kimaki session they default to `OPENCODE_SESSION_ID`, so an agent can omit the flag.

### Start the bot

```bash
kimaki [options]
```

| Option                        | Description                                                              |
| ----------------------------- | ------------------------------------------------------------------------ |
| `--data-dir <path>`           | Data directory (default: ~/.kimaki)                                      |
| `-g, --guild <guildId>`       | Server to onboard when the bot is in several                             |
| `--gateway`                   | Use the shared Kimaki bot, no Discord app needed                         |
| `--gateway-callback-url <url>`| Redirect here after the gateway install (appends ?guild_id=&lt;id&gt;)   |
| `--install-url`               | Print the install URL and exit (non-interactive onboarding)              |
| `--machine-name <name>`       | Name in this machine's category "Kimaki &lt;name&gt;" (default: hostname) |
| `--restart-onboarding`        | Choose credentials again                                                 |
| `--worktrees`                 | Use a fresh Git worktree for new sessions unless the channel overrides it |
| `--no-analytics`              | Disable anonymous usage analytics (same as KIMAKI_STRADA_ENABLED=0)      |

### `kimaki send`

```bash
kimaki send --channel <channel-id> --prompt 'add tests for the parser'
kimaki send --thread <thread-id> --prompt 'now commit it'
kimaki send --channel <channel-id> --prompt 'daily report' --send-at '0 9 * * 1-5'
```

| Option                     | Description                                                                 |
| -------------------------- | --------------------------------------------------------------------------- |
| `-c, --channel <id>`       | New thread in this channel                                                  |
| `-d, --project <path>`     | Project directory of the new thread                                         |
| `--thread <id>`            | Continue this thread (ID or URL)                                            |
| `-s, --session <id>`       | Continue this session: session ID, thread ID or thread URL                  |
| `-p, --prompt <text>`      | Prompt; thread suffixes . queue and . btw are supported                     |
| `-f, --file <path>`        | Attach a local file (repeatable)                                            |
| `-n, --name <text>`        | Thread name                                                                 |
| `--agent <name>`           | Agent ID                                                                    |
| `--model <provider/model>` | Model for the new session                                                   |
| `-u, --user <id>`          | Add this Discord user to the thread (repeatable)                            |
| `--cwd <path>`             | Existing project subfolder or linked Git worktree                           |
| `--worktree [name]`        | Create a custom Git worktree (automatic name when omitted)                  |
| `--base-branch <ref>`      | Starting ref for --worktree (default: project HEAD)                         |
| `--parent-session <id>`    | Record the parent session in session metadata                               |
| `--permission <rule>`      | Repeatable: tool[:pattern]:allow\|deny\|ask                                 |
| `--notify-only`            | Post a notification thread without a model turn                             |
| `--wait`                   | Wait until idle or input is needed, then print the session                  |
| `--send-at <when>`         | Schedule: UTC ISO date ending in Z, or cron expression (UTC)                |
| `--pre-run <command>`      | Scheduled only: run first in the project. Exit 0 starts, stdout is appended |
| `--allow-concurrency`      | Scheduled only: allow overlapping runs of this task                         |

`kimaki send` works **without a local bot** too. With `KIMAKI_BOT_TOKEN` set, it posts the request in the channel and the bot that owns the channel runs it. See [CI & Automation](../guides/ci-automation).

### Bot

| ----------------- | ----------------------------------------------------------------------------------- | ----------------------------- |
| `status`          | Bot health: running, pid, uptime, OpenCode URL and version, guilds                  | `--json`                      |
| `logs`            | Print the log file path. The bot resets the file on every start                     | `-f, --follow`                |
| `restart`         | Restart the running bot with the code on disk. Sessions keep running in OpenCode    |                               |
| `profile cpu`     | Record a CPU profile of the running bot and print the .cpuprofile path              | `-d, --duration`              |

Run `kimaki <command> --help` for the full flag descriptions. See [Debug sessions and report bugs](../guides/report-bugs.mdx) to export events and file an issue.
