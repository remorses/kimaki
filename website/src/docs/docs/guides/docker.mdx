Run Kimaki on a **VPS** the same way you run it on your laptop: one container, one persistent volume, **gateway mode**. You do not create a Discord bot. The shared Kimaki bot is installed into your server from a URL printed in the container logs.

```bash
docker compose up -d
docker compose logs -f
```

Look for a line that starts with `data: {"type":"install_url"`. Open that URL, pick your Discord server, click **Authorize**. Credentials stay on the volume, so later restarts skip this step.

## How it works

The container runs `kimaki --gateway`. On the first start Kimaki starts the OpenCode 2 service, creates local credentials, prints an **install URL**, and waits for you to authorize the shared bot. After that it connects through the [gateway proxy](../reference/gateway-architecture.mdx) and listens for Discord messages.

```diagram
  Your VPS                              Kimaki cloud                Discord
 ┌───────────────────────────────┐     ┌─────────────────────┐     ┌──────────────┐
 │  Docker                       │     │                     │     │              │
 │  kimaki --gateway             │────>│  gateway proxy      │────>│  your server │
 │  OpenCode 2 service           │     │  kimaki.dev         │     │              │
 │                               │     │                     │     │  channels    │
 │  /data  (volume)              │     └─────────────────────┘     │  + threads   │
 │    kimaki.db, kimaki.log      │                                 └──────────────┘
 │    projects/                  │
 │    opencode/ (sessions, auth) │
 └───────────────────────────────┘
```

Kimaki does not run its own OpenCode server. It uses the OpenCode 2 background service, and starts it when none runs. Session history and provider logins live in OpenCode's data folders, so they must be on the volume too.

## Dockerfile

Create a directory on the VPS, then add this **Dockerfile**. Pin a Kimaki version if you want reproducible deploys.

```dockerfile
FROM node:24-slim

RUN apt-get update && apt-get install -y git curl unzip ca-certificates \
  && rm -rf /var/lib/apt/lists/*

RUN npm install -g kimaki@latest

# OpenCode 2. Kimaki finds it in ~/.opencode/bin
RUN curl -fsSL https://opencode.ai/v2/install | bash
ENV PATH="/root/.opencode/bin:$PATH"

# Keep OpenCode sessions, logins and config on the volume
ENV XDG_DATA_HOME=/data/opencode/data \
    XDG_STATE_HOME=/data/opencode/state \
    XDG_CONFIG_HOME=/data/opencode/config

RUN mkdir -p /data/projects
WORKDIR /data

# --gateway: shared Kimaki bot, no Discord bot token
# --data-dir /data: SQLite database, credentials and log on the volume
# --machine-name: name of the Discord category, instead of the container ID
CMD ["kimaki", "--gateway", "--data-dir", "/data", "--machine-name", "vps"]
```

<Aside>
<Note>
**git** is required. OpenCode uses it for worktrees, diffs, and project detection. Without it, sessions fail in confusing ways.
</Note>
</Aside>

## docker-compose.yml

Pair the image with a **named volume**. That volume is the only state that must survive rebuilds.

```yaml
services:
  kimaki:
    build: .
    restart: unless-stopped
    volumes:
      - kimaki-data:/data
    environment:
      NODE_ENV: production
      KIMAKI_DATA_DIR: /data

volumes:
  kimaki-data:
```

`KIMAKI_DATA_DIR` lets `docker compose exec kimaki kimaki ...` commands find the same data directory without `--data-dir`. `restart: unless-stopped` starts the container again after a crash.

Start it:

```bash
docker compose up -d --build
```

Give the machine about **2 GB RAM**. OpenCode plus the bot is tight on 1 GB once a session is running.

## Get the install URL from the logs

Docker has no TTY, so Kimaki prints structured **`data:` events** on stdout. The first event is the install URL.

```bash
docker compose logs -f
```

Look for:

```
data: {"type":"install_url","url":"https://kimaki.dev/discord-install?clientId=...&clientSecret=..."}
```

Copy the `url` value, open it in a browser, select your Discord server, click **Authorize**.

```diagram
  docker compose up
          │
          v
  install_url in logs ──> open URL ──> Authorize ──> authorized ──> ready
```

| Event         | What it means                                            |
| ------------- | -------------------------------------------------------- |
| `install_url` | Open this URL once. It contains your credentials.        |
| `authorized`  | Discord install succeeded. A `guild_id` is now stored.   |
| `ready`       | The bot is connected and onboarding is done.             |
| `error`       | Something failed. Read `message`. Restart and try again. |

<Aside>
<Warning>
The install URL contains your **client secret**. Do not paste it into a public channel. Authorization waits about **5 minutes**. If you miss that window, the credentials are already on the volume. Restart the container or print the same URL again with the command below; do not wipe `/data`.
</Warning>
</Aside>

If the log scrolled away, print the URL again from the same data directory:

```bash
docker compose exec kimaki kimaki bot install-url
```

For the full event protocol, including how a host process can parse these lines, see [Programmatic Gateway](./programmatic-gateway.mdx).

## After authorization

The bot creates a `Kimaki vps` category with a **#kimaki** channel and an onboarding thread. Then:

1. Run **`/login`** in Discord and connect Claude, Codex, or an API key. See [Models & Subscriptions](../getting-started/subscriptions.mdx).
2. Clone your repositories into `/data/projects` and add a channel for each one:

```bash
docker compose exec kimaki git clone https://github.com/you/app /data/projects/app
docker compose exec kimaki kimaki project add /data/projects/app
```

You can also ask in the onboarding thread: the agent there adds channels with the same command. See [Managing Projects](../configuration/projects.mdx).

Credentials, channel mappings, OpenCode sessions, and project files stay on the volume. Rebuilding the image does not log you out.

## Access and display

Only the server owner, members with **Administrator** or **Manage Server**, and members with a role named **Kimaki** can start sessions. A role named **no-kimaki** always blocks. See [Access Control](../configuration/access-control.mdx).

To change what the bot shows in a channel, run `/verbosity` in Discord. See [Verbosity](../configuration/verbosity.mdx).

## Updating

Kimaki does not update itself. Rebuild to pull a newer `kimaki@latest` (or bump a pinned version in the Dockerfile):

```bash
docker compose up -d --build
```

The **volume** keeps `/data`, so gateway credentials, OpenCode data, and projects survive.

## Logs and shell

```bash
# follow bot output
docker compose logs -f

# bot health and OpenCode connection
docker compose exec kimaki kimaki status

# shell inside the container
docker compose exec kimaki bash
```

The Kimaki log file is `/data/kimaki.log`. It resets every time the bot starts. See [Troubleshooting](./troubleshooting.mdx) if sessions stall after the bot is online.

## One bot per machine

Each Kimaki process can only see folders **inside this container**. That is the same rule as a laptop install. To drive another machine, run another container (or a native `kimaki` process) there and install that instance into the same Discord server. See [Advanced Setup](./advanced-setup.mdx).
