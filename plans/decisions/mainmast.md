- Every project channel holds one long session (`roots[channelId]`, `thread_sessions` row keyed by the channel ID). `kimaki --no-mainmast` restores one thread per message.
- Workers are `kimaki send` threads, not `subagent` children: they reuse all thread code, work in other projects and worktrees, and users can talk to them. The `subagent` tool stays allowed, only for blocking throwaway work the user never sees (explore, lookups).
- A finished thread run sends the mainmast a synthetic `<session-finished>` item like OpenCode's subagent completion. `resume: true` only when the mainmast started it (`--parent-session`); threads of the channel and routines get `resume: false`.

- User, 2026-10-29: "mainmast session has its own warmup implementation. so that mainmast does its own wamrup while child sessions are running. so when notifications come in they dont trigger a kv cache write. and so we can disable the warmup global ... limit this to max 1.5 hours". The plugin sends OpenCode-style `session.generate` keep-alives (same prompt and 4-minute interval as OpenCode's warming) to the mainmast while its channel is busy, at most 1.5 hours after its last real request. Global `warming` is no longer needed.
- (agent) "Busy" (the mainmast or a thread of its channel runs and does not wait for the user) comes from the bot's thread views through the `mainmast.busy` lock route: the plugin cannot list sessions or their run state. The request timing stays in the plugin, because only its hooks see the exact request times that the cache TTL counts from.
- (agent) Warmup only keeps a warm cache warm: it starts at a real mainmast request, never later. A thread the user starts hours later does not rewarm a cold mainmast.
- (agent) When the warmup ends (channel idle, or the cap) the plugin compacts the mainmast if the last request used at least 100k tokens, while the cache still holds. Not a share of the window: a day-long mainmast at 190k never reached 20% of a 1M window. The warmup also lives in plugin storage (`ctx.storage`), because OpenCode reloads the plugin on every Kimaki build and that cleared the timers.
- (agent) `IDLE` stays visible in the OpenCode TUI. OpenCode v2 has no flag to hide assistant text (the TUI only hides empty text parts and synthetic messages without description), and TUI plugin slots do not cover message rows. Rewriting the provider response in `http.response` would be a hack.
- (agent) `kimaki session read` defaults to prompts and final answers; `--full` shows tool calls.
- User, 2026-10-24: "i don't think this is worth it. we should just make a plugin inject mainmast instructions so opencode will handle this automatically." The coordinator and worker role texts come from the `kimaki` plugin, derived from markers (coordinator: `threadId === channelId`; worker: `parentSessionId` or fork chain reaches a coordinator).
